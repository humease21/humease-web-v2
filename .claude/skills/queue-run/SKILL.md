# 큐 실행

상위 규칙은 CLAUDE.md §2·§3·§11 이다. 이 문서는 그 절차만 담는다.

## 큐 정의

```
queue/todo      착수 대기
queue/doing     디스패치됨
queue/review    구현 완료, 정적 리뷰 대기
queue/qa        정적 리뷰 통과, 동적 QA 대기
queue/done      완료
queue/failed    실패
queue/blocked   정보 부족 또는 동일 원인 2회 실패
logs/<id>.log   작업별 로그
```

상태는 폴더 위치로만 표현한다. 파일명 접두사·본문 상태 필드를 쓰지 않는다.
파일의 생성·이동·삭제는 Claude 만 한다. 워커에게 `queue/` 는 읽기 전용이다.
처리 순서는 `queue/todo/` 파일명 오름차순이다.
작업 id 는 큐 파일명에서 확장자를 뺀 값이다. 로그 파일명이 여기서 나온다.

## 착수 전 확인

1. `spec.md` 를 읽는다. CLAUDE.md §10 필수 항목 중 이번 작업에 필요한 것이
   비어 있으면 착수하지 않고 사람에게 되묻는다. 추측해서 채우지 않는다.
2. **세션 재개 점검을 먼저 한다** → `/session-control`. `queue/todo/` 보다 먼저다.
3. `ls queue/todo/` 로 처리 대상을 확정한다. 기억이나 이전 나열 결과를 믿지 않는다.
4. `git status --short --branch` 로 현재 브랜치와 작업 트리 상태를 확인한다.

## 처리 절차

1. `ls queue/todo/` — 가장 앞선 파일을 읽는다.
2. 목표·완료 조건·검증 방법을 추출한다. 셋 중 하나라도 추출할 수 없으면
   착수하지 않고 `queue/blocked/` 로 옮긴 뒤 사람에게 되묻는다.
3. 5분 내 완료 전제로 분해한다(CLAUDE.md §3). 넘길 규모면 착수하지 않고
   `queue/todo/` 안에서 여러 파일로 쪼갠다. 쪼갠 파일들이 원본의 목표·완료 조건·
   검증 방법을 빠짐없이 나눠 가진 것을 확인한 뒤에만 원본을 지우고,
   `logs/<원본 id>.log` 에 분할 사실과 새 id 목록을 남긴다.
4. 파일을 `queue/doing/` 으로 옮기고 `logs/<id>.log` 에 착수 시각과 워커를 적는다.
5. 난이도를 판정해 워커를 고르고 브리프를 써서 디스패치한다 → `/delegate-run`.
6. 결과를 받으면 `queue/review/` 로 옮기고 게이트를 태운다 → `/gate-route`.
7. 정적 리뷰 pass 면 `queue/qa/`, 동적 QA 까지 pass 면 `queue/done/` 으로 옮긴다.
   fail 이면 `/failure-handling` 을 따른다.
8. 커밋한다(CLAUDE.md §6). 세션 처리 상한에 도달했으면 종료하고,
   아니면 1번으로 돌아간다 → `/session-control`.

`queue/todo/` 에 파일이 남아 있고 상한에 도달하지 않았으면 턴을 종료하지 않는다.
큐가 비거나 상한에 도달하면 폴링하지 말고 보고 후 종료한다.

브리프 작성 항목은 `/delegate-run` 에 있다.

## 큐 파일 형식

형식은 자유다. Claude 가 목표·완료 조건·검증 방법을 추출할 수 있으면 된다.
사람이 쓰기 편하도록 아래를 권장하되 강제하지 않는다.

```markdown
# <작업 제목>

## 목표

## 범위
<수정 허용 경로>

## 완료조건
-

## 검증
<명령 또는 확인 절차. 없으면 spec.md 게이트 3종을 쓴다>

## QA 시나리오
<사용자 동작 검증이 필요하면 적는다. 없으면 "없음">
```

## 병렬

파일 범위가 겹치지 않는 작업이 2건 이상 대기 중이면 동시에 디스패치할 수 있다.
공유 파일(라우터 인덱스·공통 타입·설정 파일·의존성 매니페스트)을 건드리는 작업은
단독으로 순차 처리한다. 애매하면 순차로 한다.
동시 실행하는 워커는 각각 격리된 작업 경로에서 돌린다 → `/delegate-run`.
게이트는 묶음이 아니라 큐 파일 1건 단위로 태운다.

## 로그

작업마다 `logs/<id>.log` 에 남긴다(CLAUDE.md §11). 담을 것은
착수 시각과 워커, 게이트 판정과 근거, 실패 원인과 재현 절차,
허위 보고 사실, QA 생략 사유다.
로그 없이 `queue/done/` 으로 옮기지 않는다.

권장 형식 — 한 줄 하나, 시각은 ISO 8601.

```
2026-09-06T14:20:00+09:00 착수 worker=codex model=<spec.md 라우팅값> effort=<값>
2026-09-06T14:27:10+09:00 결과 status=ok changed=3 evidence=<git diff --stat 마지막 줄>
2026-09-06T14:31:02+09:00 게이트정적 reviewer=agy verdict=pass 근거=<한 줄>
2026-09-06T14:38:44+09:00 게이트동적 verdict=pass 증거=<경로> / 또는 생략사유=<사유>
2026-09-06T14:39:10+09:00 done 커밋=<해시>
```

## 사람 확인이 필요한 경우

임의 판단으로 진행하지 않고 즉시 되묻는다.

- CLAUDE.md §7 안전 항목에 걸리는 작업 — 큐에 담긴 지시서라도 자동 실행하지 않는다
- `spec.md` 필수 항목 미기재
- 큐 파일에서 목표·완료 조건·검증 방법을 추출할 수 없음
- 제품 방향·데이터 구조·서비스 정책 결정
- 외부 자격증명·계정·권한 입력 필요
- E2E 가 없어 동적 QA 를 자동 통과시킬 수 없는 경우 → `queue/qa/` 에 두고 대기

되묻는 동안 다른 큐 항목은 계속 진행한다.

## 보고

큐 파일 1건을 끝낼 때마다 한 줄로 출력한다.

```
<id> / 워커 / 정적리뷰 주체 / 동적QA 주체 / 변경 파일 수 / 결과
```

세션이 끝나면 처리 결과 전체를 표로 출력하고, `queue/done` · `queue/failed` ·
`queue/blocked` 각각의 목록을 요약한다. **상한에 걸려 종료한 경우 남은
`queue/todo/` 건수와 파일명을 반드시 함께 보고한다** — 큐가 빈 것과
상한에 걸린 것을 사람이 구분할 수 있어야 한다. 보고 채널은 `spec.md` 를 따른다.
없으면 대화로 보고한다. 보고 언어는 한국어다(CLAUDE.md §8).
