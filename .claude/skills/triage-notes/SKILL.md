# 인박스 분류

상위 규칙은 CLAUDE.md §12 다. 규칙을 늘리는 유일한 통로가 이 절차다.

## 인박스

리포 루트 `add-process.md` 가 인박스다. 운영 중 알게 된 것을 원문 그대로 적는다.
규칙 파일에 바로 쓰지 않는다. 정리는 이 스킬이 한다.

## 절차

1. `add-process.md` 를 읽는다. 비어 있으면 "인박스 비어 있음" 만 보고하고 종료한다.
2. 항목마다 아래 표로 목적지를 판단해 **제안한다.** 이 단계에서 파일을 만들거나 고치지 않는다.
3. 승인받은 항목만 이관한다. 승인 없이 파일을 생성·수정하지 않는다.
4. 이관한 원문은 `add-process.archive.md` 로 옮기고 `add-process.md` 에서 지운다.
   아카이브 없이 인박스 원문을 삭제하지 않는다.
5. 최종 보고 — 생성·수정한 파일 경로 목록과 `CLAUDE.md` 최종 줄 수.

## 분류 기준

| 항목 성격 | 목적지 |
|---|---|
| 항상 참인 사실·금지 규칙 | `CLAUDE.md` (200줄 넘으면 스킬로 뺀다) |
| 프로젝트 고유값 — 명령·모델·경로·계정·규약 | `spec.md` (사람이 고친다. 제안만 한다) |
| 2회 이상 반복된 절차·체크리스트 | `.claude/skills/<이름>/SKILL.md` |
| 워커가 지켜야 할 규칙 | `AGENTS.md`(Codex) 또는 `GEMINI.md`(agy) |
| 긴 표·설정법·레퍼런스 | `docs/<주제>.md` (스킬에서 한 줄로 참조) |
| 1회성 메모 | 아카이브만. 승격 금지 |
| 반드시 실행돼야 하는 것 | 훅 후보로 보고만 한다. 직접 만들지 않는다 |

워커는 `CLAUDE.md` 와 `.claude/skills/` 를 읽지 못한다. 워커가 지켜야 할 규칙을
그 두 곳에만 적으면 전달되지 않는다. `AGENTS.md`·`GEMINI.md` 또는 브리프에 적는다.

## 작성 규칙

- `CLAUDE.md` 는 200줄 미만을 유지한다. 절차성 내용은 스킬로 뺀다.
- 같은 규칙을 `CLAUDE.md` 와 스킬 양쪽에 쓰지 않는다. `CLAUDE.md` 에는 포인터만 둔다.
- 스킬 본문은 짧게. 긴 자료는 별도 `.md` 로 분리해 한 줄로 연결한다.
- 프로젝트 고유값을 `CLAUDE.md` 나 스킬에 쓰지 않는다. `spec.md` 에만 둔다.
- 부작용 있는 절차는 `disable-model-invocation: true` 를 붙인다.
- `@import` 는 토큰 절감 효과가 없으므로 쓰지 않는다.

## 금지

- 승인 없이 파일 생성·수정
- 아카이브 없이 인박스 원문 삭제
- `CLAUDE.md` 와 스킬에 같은 내용 중복 유지
- 새 규칙 창작 — 인박스에 없는 것을 규칙으로 만들지 않는다
- 파일 전체 출력 — 변경된 부분만 보여준다
