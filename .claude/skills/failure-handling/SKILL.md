# 실패 처리

상위 규칙은 CLAUDE.md §5 다. 자동 재시도는 없다.

## 원칙

동일 원인 2회 실패는 `queue/blocked/` 로 옮기고 사람 판단을 기다린다.
"동일 원인" 은 증상이 아니라 원인 기준이다. 같은 파일에서 다른 이유로 두 번
막힌 것은 서로 다른 원인이다. 판단이 애매하면 동일 원인으로 세고 blocked 로 올린다.

재시도 횟수는 Claude 가 센다. 워커에게 세게 하지 않는다.
횟수와 원인은 `logs/<id>.log` 에 남긴다. 로그가 없으면 카운트가 없는 것이다.

## 유형별 처리

### 워커가 blocked 로 반환

정보 부족·선행 산출물 부재·규모 초과다. 실패가 아니다.

- 규모 초과 — 브리프를 5분 단위로 다시 쪼개 재디스패치한다. 카운트하지 않는다.
- agy 가 5분 내 불가로 반환 — Codex 로 재라우팅한다. 실패로 세지 않는다(CLAUDE.md §1).
- 정보 부족 — 큐 파일에 그 정보가 있으면 브리프를 보강해 재디스패치한다.
  큐 파일에도 없으면 `queue/blocked/` 로 옮기고 사람에게 되묻는다.

### 워커가 failed 로 반환

1회차 — 브리프의 모호한 지점을 특정해 보강한 뒤 같은 워커에 재위임한다.
2회차 — 동일 원인이면 `queue/blocked/` 로 옮긴다. 다른 원인이면 1회차로 취급한다.

같은 브리프를 그대로 다시 보내지 않는다. 그건 재시도가 아니라 반복이다.

### 타임아웃 · 결과물 없음

`dispatch_command` 의 타임아웃에 걸렸거나, 프로세스가 끝났는데 `result.json`
또는 보고 JSON 이 없으면 원인 불명 실패다(CLAUDE.md §3).

- 자동 재시도하지 않는다.
- 미완료 중간물은 되돌리려 하지 않는다. 워커 작업 경로를 그대로 버린다.
- 분해가 잘못된 것으로 보고 브리프를 다시 쪼갠다. 쪼갤 여지가 없으면 blocked.
- 로그에 마지막 성공 지점과 남은 완료 조건을 적는다.

### 게이트 반려

fail 사유가 브리프 안의 것인지 먼저 확인한다.
브리프에 없던 요구로 fail 이 났으면 그건 리뷰어 과잉이므로 브리프를 고쳐
다시 태운다. 카운트하지 않는다.

- 단순 — 타입 오류, 오타, import 누락, null·빈 배열 방어, 포맷, 누락분.
  구현자에게 되돌려 재수정 후 다시 게이트①.
- 복잡 — 로직·알고리즘 오류, 설계 결함, 여러 파일이 얽힌 문제.
  Codex 에 재설계를 맡기고 그 안대로 다시 구현한다.
- 같은 원인으로 2회 반려 — 구현이 아니라 지시가 틀린 것으로 본다.
  `queue/blocked/` 로 옮기고 큐 파일부터 다시 볼 것을 사람에게 제안한다.

재수정 결과는 반드시 다시 게이트①부터 태운다. 부분 재검토로 통과시키지 않는다.

### 쿼터 소진 · 워커 미가용

- 재시도하지 않는다. 대체 워커로 갈아타지 않는다.
- **Claude 가 대신 구현하거나 대신 리뷰하지 않는다.** 큐를 멈추고 보고한 뒤 대기한다.
  쿼터는 시간이 지나면 회복되므로 기다리는 것이 손해가 아니다.
- `logs/<id>.log` 에 "<워커> 미가용 — 대기" 한 줄을 남긴다.
- 큐 파일은 `queue/doing/` 에 그대로 둔다. failed 로 옮기지 않는다.

### 인증 만료 · 자격 소실

재시도 불가다. 즉시 사람에게 알리고 복구에 필요한 조치를 명시한다.
자격증명 변경은 사람 승인 사항이므로 Claude 가 처리하지 않는다(CLAUDE.md §7).

### E2E 인프라 실패

QA 실행 자체가 안 되면 설치·설정 절차를 1회 재시도한다.
그래도 안 되면 **QA 미실행 상태를 통과로 위장하지 않는다.**
`queue/qa/` 에 두고 사유를 로그에 적은 뒤 사람 확인을 기다린다.

## 허위 보고

허위 보고 탐지가 최우선이다(CLAUDE.md §4). 아래는 재시도 대상이 아니라
즉시 fail 이며, 발견 사실 자체를 `logs/<id>.log` 에 반드시 기록한다(CLAUDE.md §11).

- 빈 diff 를 완료로 보고
- 브리프와 무관한 변경을 완료로 보고
- `evidence` 가 명령 출력 원문이 아니라 요약·재작성
- 실행하지 않은 검증을 pass 로 표기
- 미검증 항목을 통과로 표기
- 테스트를 skip·삭제·완화해 통과시킴
- 존재하지 않는 파일·명령·결과를 보고에 기재

같은 워커 세션에서 재수정시키지 않는다. fresh 세션에 재위임하고,
2회차에도 같은 유형이 나오면 `queue/blocked/` 로 올려 사람 판단을 받는다.

## blocked 로 옮길 때

`queue/blocked/` 로 파일을 옮기고 `logs/<id>.log` 에 아래를 남긴다.

```
blocked 사유=<한 줄>
  시도=<1회차 원인 / 2회차 원인>
  재현=<명령과 출력 요지>
  마지막 성공 지점=<어디까지 됐는지>
  재개 조건=<무엇이 정해지면 다시 큐에 올릴 수 있는지>
```

blocked 건은 자동으로 다시 꺼내지 않는다. 사람이 재개 조건을 채워 지시하면
그때 `queue/todo/` 로 되돌린다.

## 큐 진행

한 건이 failed 또는 blocked 로 확정돼도 큐를 멈추지 않는다.
다음 큐 파일로 넘어간다. 예외는 쿼터 소진과 인증 만료 — 이때는 큐를 멈춘다.
실패·blocked 건은 최종 보고에 반드시 포함한다.
