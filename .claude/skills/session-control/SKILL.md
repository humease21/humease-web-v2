# 세션 제어

상위 규칙은 CLAUDE.md §2 다. 큐 처리 절차 자체는 `/queue-run` 에 있다.

이 문서는 두 가지를 다룬다. 세션이 **예기치 않게 끊겼을 때** 남은 작업을 회수하는
절차와, 세션을 **의도적으로 끊는** 상한이다. 둘을 섞지 않는다 — 앞은 사고 복구고
뒤는 정상 종료다.

## 세션 재개

세션은 중단된다 — 컨텍스트 압축, 사용자 인터럽트, 프로세스 종료.
중단 시점에 `queue/doing/`·`queue/review/`·`queue/qa/` 에 있던 파일은
아무도 꺼내주지 않으면 영구히 방치된다. `queue/todo/` 만 나열하면 보이지 않는다.

**모든 큐 세션은 시작할 때 세 폴더를 먼저 나열한다.**

```bash
ls queue/doing/ queue/review/ queue/qa/
```

비어 있으면 정상 시작이다. 파일이 있으면 이전 세션의 잔여물이므로 아래를 따른다.
중단은 실패가 아니다. `/failure-handling` 의 재시도 횟수에 세지 않는다.

1. `logs/<id>.log` 를 읽어 어디까지 갔는지 확인한다. 로그가 없으면 착수 직후
   중단된 것이다.
2. 워커 결과물(`result.json` 또는 보고 JSON)이 있는지 확인한다.
   프로세스 생존 여부로 판단하지 않는다 — 판정 근거는 결과물뿐이다.

| 위치 | 결과물 | 처리 |
|---|---|---|
| `doing/` | 없음 | `todo/` 로 되돌리고 로그에 중단 기록. 워커 작업 경로는 버린다 |
| `doing/` | 있음 | `/delegate-run` 결과 수령 확인부터 이어서 진행 |
| `review/` | — | 게이트① 판정 로그가 있으면 그 다음부터, 없으면 게이트①부터 |
| `qa/` | — | 게이트② 판정 로그가 있으면 그 다음부터, 없으면 게이트②부터 |

**처음부터 다시 하지 않는다.** 대상 파일의 현재 상태를 먼저 읽고 이미 반영된
변경은 건너뛴다. 이미 통과한 게이트를 다시 태우지 않는다 — 단, 재개 후
코드가 바뀌었으면 게이트①부터 다시 태운다.

되돌리거나 이어받은 사실을 `logs/<id>.log` 에 한 줄로 남긴다.

```
2026-09-06T15:02:11+09:00 재개 이전위치=doing 결과물=없음 조치=todo 로 복귀
```

## 세션 처리 상한

한 세션에서 처리할 큐 파일 수의 상한이다. **기본값 5건.**
`spec.md` 에 「세션 처리 상한」이 있으면 그 값을 쓴다.

상한이 필요한 이유는 시간이 아니라 컨텍스트다. 한 건은 큐 파일 읽기 · 브리프 작성 ·
디스패치 · 결과 판정 · 게이트 3종 실행 · 리뷰 수령 · 커밋을 거치며 컨텍스트를 쓴다.
상한 없이 큐를 끝까지 돌면 세션이 압축되고, 압축된 세션은 앞서 내린 게이트 판정의
근거를 잃는다. 근거를 잃은 판정은 판정이 아니다.

### 세는 방법

- `done` · `failed` · `blocked` 중 하나로 **확정된** 건수를 센다. 진행 중인 건은 세지 않는다.
- 세션 재개로 이어받은 건도 센다.
- 브리프 재분할·워커 재라우팅은 같은 건이므로 중복해서 세지 않는다.
- 큐 파일 분할로 늘어난 건수는 새 id 기준으로 각각 센다.

### 상한 도달 시

- **진행 중인 건은 끝까지 마친다.** 게이트 통과와 커밋까지가 한 건이다.
  `queue/doing/`·`review/`·`qa/` 에 파일을 남긴 채 종료하지 않는다.
  중간에 끊으면 다음 세션이 「세션 재개」로 회수해야 하고, 그건 상한의 목적이 아니다.
- 그다음 건에는 착수하지 않는다.
- 남은 `queue/todo/` 목록과 개수를 보고에 포함한다.
- 상한 도달 사실은 `logs/` 에 적지 않는다. 작업 사정이 아니라 세션 사정이다.

상한은 큐를 멈추는 것이 아니라 세션을 끊는 것이다. 다음 세션이 「세션 재개」
절차로 이어받는다. 사람이 "끝까지 돌려라" 라고 명시하면 상한을 무시한다.
