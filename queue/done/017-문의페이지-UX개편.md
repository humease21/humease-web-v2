## 0. 완료 시 기대 결과 / 대표님 테스트 정상 프로세스

### 0-1. 완료 시 기대 결과
- `/contact` 첫 화면에서 데스크톱 기준 좌측에는 기존 문의 히어로 카피가, 우측에는 실제 문의 폼이 동시에 노출된다.
- 대표님이 문의 페이지 진입 후 하단으로 길게 스크롤하지 않아도 바로 문의 입력을 시작할 수 있다.
- 모바일/좁은 화면에서는 좌측 히어로 → 문의 폼 순서의 1열 구조로 자연스럽게 배치된다.
- 현재 폼 하단에 길게 노출되는 개인정보 수집·이용 동의 전문은 제거하고, `개인정보 수집·이용에 동의합니다` 체크박스 + `내용 보기` 버튼만 노출한다.
- `내용 보기` 클릭 시 개인정보 수집·이용 동의 전문이 모달 팝업으로 열린다.
- 동의 체크 전에는 `문의 보내기`가 비활성화되며, 동의 후에만 제출 가능하다.
- `관심 분야` 드롭다운의 모든 옵션 텍스트가 다크 테마에서도 명확하게 보인다.
- 기존 개인정보처리방침/이용약관/문의 저장/Discord 알림/Retention 정책 및 법률 문구는 변경하지 않는다.
- 기존 문의 제출 로직과 Supabase 저장, Discord 비식별 알림 구조는 유지한다.

## 2. 목표

현재 `/contact`는 상단 히어로 이후 별도 섹션에 문의 폼이 배치되어 있어 실제 문의 입력을 시작하려면 상당한 스크롤이 필요하다.

이번 개편의 목표는 다음과 같다.

1. 문의 페이지 첫 화면에서 바로 문의 입력을 시작할 수 있게 한다.
2. 기존 휴미즈의 다크/프리미엄 비주얼 톤은 유지한다.
3. 개인정보 수집·이용 동의 전문은 필요할 때만 모달로 열람하도록 단순화한다.
4. 관심 분야 드롭다운의 심각한 가독성 문제를 해결한다.
5. 기존 개인정보 정책, 문의 저장, Discord 알림, 관리자 문의 관리 기능은 그대로 유지한다.
6. 데스크톱과 모바일 모두에서 입력 흐름을 짧고 명확하게 만든다.

## 3. 요구사항

### 3-1. 문의 페이지 첫 화면 2열 구조

#### 데스크톱
`lg` 이상 화면에서는 현재 상단 히어로를 다음과 같이 재구성한다.

- 좌측 영역
  - 상단 라벨: `문의`
  - H1: `데이터와 AI, 다음 단계로`
  - 기존 설명 문구 유지
  - 필요 시 기존 이메일 CTA 유지 가능
- 우측 영역
  - 실제 `프로젝트 상담` 문의 폼
  - 별도 하단 섹션으로 밀지 말고 히어로와 같은 첫 화면 영역에 배치

#### 핵심 UX
- `/contact` 진입 즉시 폼 입력이 가능해야 한다.
- 현재처럼 문의 폼을 보기 위해 화면 하단으로 길게 스크롤해야 하는 구조는 제거한다.
- 우측 문의 폼의 시작부가 첫 viewport 안에 명확하게 보여야 한다.
- 폼 전체가 viewport에 100% 다 들어올 필요는 없지만, 최소한 다음 필드는 첫 화면에서 시작되어야 한다.
  - 회사명
  - 담당자명
  - 이메일

#### 레이아웃 권장
- 전체 컨테이너 최대 폭은 기존 사이트 토큰/레이아웃 체계를 따른다.
- 좌측과 우측 비율은 실제 코드와 시각 밸런스를 보고 결정하되, 문의 폼이 지나치게 좁아지지 않게 한다.
- 기존 히어로 우측 오브젝트/비주얼은 문의 폼과 충돌할 경우 축소·재배치·배경 요소화할 수 있다.
- 기존 페이지의 시각적 정체성을 버리고 일반적인 흰색 문의 페이지로 바꾸지 않는다.

### 3-2. 모바일/태블릿 반응형

#### 모바일
- 1열 구성
- 히어로 카피 → 문의 폼 순서
- 불필요한 상하 여백 최소화
- 폼이 지나치게 아래로 밀리지 않게 한다.
- 좌우 여백은 기존 모바일 디자인 토큰 준수
- input/select/textarea는 화면 너비를 넘지 않아야 한다.

#### 태블릿
- 실제 화면 폭에서 2열이 비좁으면 1열로 전환
- 억지로 2열을 유지해 폼 가독성을 떨어뜨리지 않는다.

#### 필수 검증 폭
- 320px
- 390px
- 430px
- 768px
- 1440px
- 1920px

### 3-4. 관심 분야 Select 가독성 버그 수정

현재 현상:
- Select를 열면 옵션 영역은 밝은 배경인데 옵션 글자도 매우 밝아서 사실상 읽을 수 없음
- 첨부 스크린샷 기준 `Enterprise Data`, `eDiscovery`, `내부 통제` 등 모든 옵션 가독성이 심각하게 낮음

#### 요구사항
- Select 닫힘 상태에서 placeholder/선택값이 명확하게 보여야 한다.
- Select 열림 상태에서 모든 option 글씨가 명확하게 보여야 한다.
- hover / selected / focus 상태도 읽을 수 있어야 한다.
- 다크 테마와 네이티브 option popup의 색상 충돌을 해결한다.
- Chrome / Edge / Safari / 모바일 환경을 고려한다.

#### 구현 우선순위
1. 먼저 native `<select>` 유지
2. `select`, `option`의 text/background/focus 스타일을 안정적으로 보정
3. 브라우저 제약으로 정상 보장이 어렵다고 실제 검증된 경우에만 custom listbox 검토

#### custom select 전환 시 필수
- Tab 이동
- Arrow Up/Down
- Enter 선택
- ESC 닫기
- ARIA label
- 현재 선택 상태
- placeholder 상태
- focus-visible
- 키보드만으로 전체 조작 가능

단순히 디자인 때문에 custom select로 교체하지 않는다.

### 3-5. 개인정보 수집·이용 동의 UI 간소화

현재:
- 개인정보 수집·이용 동의 전문 전체가 폼 하단에 긴 박스로 상시 노출됨
- 사용자가 제출 버튼까지 가기 위해 불필요하게 긴 내용을 스크롤해야 함

변경 후:
- 폼에는 아래만 기본 노출

`□ 개인정보 수집·이용에 동의합니다.  [내용 보기]`

또는 디자인상 동등한 구조

#### 필수
- 체크박스는 별도
- `내용 보기`는 별도 버튼/링크
- 내용 보기를 클릭하지 않아도 동의 체크 가능
- 동의하지 않으면 제출 불가
- 동의 체크 상태는 기존 submit validation과 연결
- 개인정보처리방침 링크가 필요하다면 모달 내부 또는 짧은 안내부에서 제공 가능

### 3-6. 개인정보 수집·이용 동의 모달

`내용 보기` 클릭 시 모달 팝업 표시

#### 모달 구성
- 제목: `개인정보 수집·이용 동의`
- 현재 Production에 반영된 V1.0 동의 전문
- 개인정보처리방침 링크
- 닫기 버튼

#### 동작
- X/닫기 버튼
- ESC
- 오버레이 클릭
- 모달 열릴 때 background scroll lock
- 닫힐 때 기존 스크롤 위치 복원
- focus trap
- 최초 focus 적절히 지정
- 닫힌 뒤 `내용 보기` 버튼으로 focus 복귀
- 모바일에서 화면 밖으로 잘리지 않음
- 내용이 길면 모달 내부 스크롤

#### 중요한 제한
- 이번 요청은 개인정보 동의 **표현 방식**을 바꾸는 것
- 법률 문구 자체를 새로 쓰거나 축약하지 않는다.
- 개인정보처리방침 V1.0의 보유기간/국외이전/Discord 비식별화 등 확정 내용을 임의 수정하지 않는다.

### 3-7. 문의 보내기 버튼 상태

#### 기본
- 필수값 미입력 → 제출 불가
- 개인정보 동의 미체크 → 제출 불가
- 제출 중 → 중복 제출 방지
- 성공 → 기존 성공 UX 유지 또는 더 명확하게 개선
- 실패 → 사용자가 재시도 가능한 오류 표시

#### 금지
- 단순 색상만으로 disabled 여부를 표현하지 않는다.
- submit 중 여러 번 클릭되어 중복 row가 생성되면 안 된다.

### 3-8. 폼 시각 정리

다음 방향으로 정리한다.

- 라벨 대비 강화
- input/select/textarea 높이와 간격 통일
- 필수 항목 `*` 일관성 유지
- focus 상태 명확화
- 오류 메시지와 입력 필드 관계 명확화
- textarea는 너무 작지 않게 유지
- 우측 폼 영역이 과도하게 길어 보이지 않도록 시각적으로 정리

권장 흐름:
1. 기본 정보
2. 관심 분야 / 문의 내용
3. 개인정보 동의
4. 문의 보내기

단, 실제 DB 구조나 payload를 섹션 구분 때문에 변경하지 않는다.

## 8. Antigravity 사후 점검 지침

구현 및 배포 완료 후 Antigravity는 READ-ONLY로 다음만 점검한다.

1. `/contact` 데스크톱 첫 화면에서 좌측 카피 + 우측 문의 폼이 동시에 노출되는가
2. 모바일에서 1열 스택이 정상인가
3. 개인정보 동의 전문이 상시 긴 본문으로 노출되지 않는가
4. `내용 보기` 모달이 정상 동작하는가
5. V1.0 전문이 원문과 동일한가
6. 동의 전 제출이 차단되는가
7. 관심 분야 모든 옵션이 읽히는가
8. 기존 Supabase 문의 저장 구조가 유지되는가
9. Discord 비식별 정책이 유지되는가
10. 관리자 문의 조회가 정상인가
11. 기존 SEO/robots/sitemap/llms 영향이 없는가
12. desktop/mobile overflow가 없는가

판정:
- PASS
- 반려
- 재조사 필요

Antigravity는 수정하지 않는다.
